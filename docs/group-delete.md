# P2-05：删除分组配置（可见验收待补）

2026-09-25。按计划的分组管理顺序实现“删除分组”。此操作只从 LiteFences 配置中移除选定分组及其项目引用，**不删除、不移动任何源文件或目录**。纯数据 `delete_group` 先验证现有配置和目标 ID，再移除目标，返回原索引与完整组供失败回退；`next_group_id`/`next_item_id` 保持单调，不复用 ID。未找到组或配置无效时不修改配置。

UI 会话只在已加载、可写、无在途保存时接受删除，仍由单个后台 I/O 工作者自动保存。提交失败、保存失败或后台中断时按原顺序恢复组；成功后重启只保留未删除的组。普通窗口左侧“删除所选分组（仅配置）”按钮采用两次点击确认：第一次只提示，再次点击相同选中组才提交；切换分组、按 Esc、切离窗口或执行其它操作会解除确认态。此处没有源文件删除命令。

隐藏 `delete` 与 `ui-delete` 使用项目独立绝对 `--data-dir`。`ui-delete` 通过实际 HWND 列表与按钮命令验证首击不删、二击只删第二组、其它字段和 ID 分配器不变、重启不再出现该组。Debug/Release 全 feature 各 120 项 Rust 测试、36 个隐藏配置窗口场景、全/无默认 feature 严格 Clippy、格式、Release 构建和 3 次窗口生命周期 smoke 通过。报告：`artifacts/config-window-c72c8d396d8d4693a0135f3ad03169d6/results.json`。低成本 gpt-6-luna 子 agent 分别负责纯数据规则及 UI 回归脚本，主 agent 负责保存回退和 Win32 集成；纯数据测试的一处错误断言由主 agent 修正。
