# 桌面启动器（M1）使用与验证说明

程序：`LiteFencesDesktop.exe`（约 200 KB）
源：`src/bin/litefences_desktop.rs`、`src/bin/litefences_desktop/`
计划：见 [开发计划书-v2.md](../开发计划书-v2.md)

## 怎么用

1. 双击 `LiteFencesDesktop.exe`，不会出现窗口，只在通知区加一个图标。
2. 在桌面空白处**双击** → 整屏虚化，桌面图标铺成居中网格。
3. **双击某个图标** → 用系统关联程序打开，面板收起。
4. **单击空白处** 或 **Esc** → 收起面板，桌面图标恢复原样。
5. 退出：托盘右键 → “退出 LiteFences”，或按 `Ctrl+Alt+Q`。
6. 快捷键：`Ctrl+Alt+Space` 唤出/收起。

双击桌面上的图标本身不会弹面板，仍然按系统默认方式打开——只有点在空白处才算“唤出”。

## 命令行参数

| 参数 | 作用 |
| --- | --- |
| `--blur=auto\|accent\|backdrop\|dim\|off` | 虚化实现。默认 `auto`：先试亚克力，再试 DWM 系统背景，最后深色底 |
| `--no-hide-desktop-icons` | 面板显示期间不隐藏原生桌面图标 |
| `--show-ms=3000` | 启动即显示面板 N 毫秒后自动退出（演示/排障） |
| `--self-test` | 不显示界面，检查虚化、图标枚举、布局、分组与拖放注册，结果写入数据目录并返回退出码 |
| `--drop-test=<路径[;路径…]>` | 排障：把给定路径当成一次外部拖入投给面板，验证拖放链路后退出；结果写 `drop-test.txt`，悬停画面写 `drop-hover.bmp` |

## 数据与日志

- 数据目录：`%LOCALAPPDATA%\LiteFencesDesktop\`
  - `launcher.log`：有界日志（512 KiB 轮换）
  - `icons-hidden.flag`：只在面板显示期间存在；若残留说明上次异常退出，下次启动会先恢复桌面图标
- 目录不可写时依次回退到程序目录 `logs\` 与临时目录。

## 2026-10-18 第二轮修复（用户实测反馈）

| 反馈 | 定位 | 处理 |
| --- | --- | --- |
| 通知区没有该程序 | 程序是从受限环境（低完整性级别）启动的，`Shell_NotifyIcon` 被系统拒绝（err=5）；正常双击启动不会 | 启动时检测完整性级别，低于中等级别就弹窗询问是否通过资源管理器以正常权限重启；托盘失败时 3 秒后重试一次；收到 `TaskbarCreated`（Explorer 重启）自动重新添加；首次添加发气泡提示，指向 Win11 的 `^` 折叠区 |
| 呼出后点图标打不开程序 | 原设计要双击图标才启动，且双击判定在受限环境下易被吞 | 改为**单击图标即启动**（双击仍然有效）；每次点击都写日志（坐标、命中序号、程序路径），便于再排查 |

顺带修正：

- 浮层改为 `HWND_TOPMOST`（收起时取消置顶）：之前用 `HWND_TOP`，别的窗口一被激活就把面板盖住了。
- 修掉了动画期间重复绘制导致的文字残影（改为只改整体透明度，不再移动图标）。
- 面板底部加了一行操作提示。

验证：截图确认面板正常绘制、虚化与提示可见、`TaskbarCreated` 重试路径已接；托盘在正常权限下的成功路径仍需人工确认。

## 2026-10-18 第三轮：卡顿修复

用户反馈（管理员权限下）：“打开的时候鼠标移动有一丁点卡顿”。

定位到的两个原因都在 UI 线程上：

1. **图标扫描阻塞消息循环**：每次唤出都会同步枚举桌面并逐个 `SHGetFileInfoW` 取图标。实测冷启动一次扫描 13.8 秒、热一点也要 1.9–3.3 秒（个别快捷方式单个就要 400–500ms）。这段时间消息循环停转，低层鼠标钩子（全局 WH_MOUSE_LL）也跟着延迟，所以是“全系统鼠标发涩”，不只是面板里。
2. **悬停时整屏重绘**：鼠标在图标间移动会触发整窗口重绘（81 个图标 + 162 段文字），每次几十毫秒。

处理：

- 图标扫描移到**后台线程**（`std::thread` + channel + `WM_APP_SCAN`），面板立即出现，扫描完成后自动填充网格；启动时立刻预热一次，之后的唤出直接命中缓存（桌面目录 mtime 变化时才重扫）。
- 增加按需重绘：只画与 `rcPaint` 相交的格子。
- 去掉悬停描边：亚克力/玻璃表面上 GDI 无法“擦除”已画像素，移开鼠标会留残影；等换成逐像素 alpha（`UpdateLayeredWindow`）再恢复高亮。
- 入场动画从 150ms/16ms 一帧调整为 120ms/24ms 一帧，减少分层窗口合成次数。

结果：单次唤出耗时从 3–14000ms 降到 **0–3ms**（扫描在后台，不阻塞）。

副作用与取舍：

- 启动后约 0.2–2 秒内图标才铺满（后台扫描），期间面板是空的但可交互、可关闭。
- 没有鼠标悬停高亮。要恢复需要改成逐像素 alpha 重绘，单次重绘成本会上来（约 10–20ms），放到 M2 一起做。

## 2026-10-18 第四轮：文字消失与自抓屏

现象：用户机器上（管理员实例）图标正常、但所有文字和 ＋ 方块不渲染；受限权限实例却正常。

排查与结论：

- 日志里 `DrawText返回=21`，说明 GDI 认为画成功了；问题在窗口合成，不在字体、坐标或布局。
- 根因：为做淡入用了 `WS_EX_LAYERED` + `SetLayeredWindowAttributes`。分层窗口按像素 alpha 合成时，GDI 文字写入的 alpha 位没被置位，文字整段被丢弃；`DrawIconEx` 画的是位图（自带 alpha）所以不受影响。
- 修复：去掉分层窗口，淡入改成调亚克力浓度（内容只画一次、不重绘），字体改灰度抗锯齿（`ANTIALIASED_QUALITY`）。

顺带加的排障能力（保留在正式版）：

- `--capture=<bmp>`：演示模式下面板显示后自动抓屏。
- 托盘菜单「抓取面板画面（排障）」：从正在运行的实例抓当前面板到 `%LOCALAPPDATA%\LiteFencesDesktop\panel-capture.bmp`。
- `capture-panel.cmd`：双击即用，独立实例打开面板并抓图。
- 坑：`--capture` 必须在释放 DIB 之前写出像素，否则写文件报 1784（缓冲区无效）。

## 2026-10-18 第五轮：文字彻底修好（自绘磨砂底板）

结论性实验：同一份 exe、同一组参数，`--blur=dim`（不透明深色底）文字正常，`accent`（透明亚克力）文字消失。据此确认：

> 透明背景下，GDI 画进窗口的文字像素在 DWM 合成时被丢弃；`DrawIconEx` 的位图自带 alpha 所以存活。

于是放弃系统亚克力，改用 `BlurMode::Frost`（默认）：

1. 唤出前抓一张桌面（此时桌面图标已隐藏）；
2. 缩到 1/10，三次盒式模糊，压暗并轻微偏冷；
3. 作为**不透明底板**铺满窗口，图标、文字、＋、提示都画在它上面。

代价：底板是“唤出那一刻”的快照，不再是实时模糊；打开多约 40ms（实测 39ms）。换来任何机器上文字都可见。

顺带：

- 面板内所有文字共用**同一个字体**、只 `SelectObject` 一次（之前每个图标名都建一次字体，是不稳定因素）。
- 托盘菜单新增「开机自启（已开启/已关闭）」，只写 `HKCU\...\Run` 下 `LiteFencesDesktop` 一个值；也可用 `--autostart=on|off` 设置。
- 排障快捷键 `Ctrl+Alt+F12` 抓当前面板（早/晚两张），托盘菜单也有同名项。




## 2026-10-24 第六轮：把文件直接拖进面板（OLE 拖放）

新增模块 `src/bin/litefences_desktop/drop_target.rs`：浮层窗口注册 OLE `IDropTarget`。

语义（沿用旧面板的安全边界）：

- **只加引用**：拖进来的文件/文件夹/快捷方式记进面板（新项写入 `custom-icons.txt`），归到鼠标松手时所在的分组；
  从不复制、移动或删除源文件。
- 效果协商只返回源端允许的 LINK，其次 COPY，**永不返回 MOVE**；只接受 `CF_HDROP` 本地路径，一次最多 256 项。
- 悬停时整块分组描边 + 标题行高亮，告诉用户松手落到哪个组；落在工具条区域则不接受。
- 松开后底部提示条显示「加入『其它』2 项 / 跳过 2 项（已在面板或不可用）」，4 秒后自动消失。
- 已经在面板里的路径不会重复记录（顺带修掉了「扫描未完成时重复写 `custom-icons.txt`」的隐患）；
  不在目标组时会移入目标组；目标组折叠时自动展开。
- 面板每次唤出都重建窗口，所以拖放目标跟着窗口注册/注销（`ensure_window` 销毁前先 `RevokeDragDrop`）。

排障入口 `--drop-test="A;B"`：直接构造真实 Shell 数据对象（单项走 `IShellItem`、多项走 PIDL 数组）投递
`DragEnter/DragOver/Drop`，并检查项数、分组归属、`custom-icons.txt` 持久化，通过则退出码 0。

本机验证（部署目录 `E:\note\LiteFencesDesktop\LiteFencesDesktop.exe`，数据目录用环境变量隔离到 `E:\note\.build\dt*`）：

| 场景 | 结果 |
| --- | --- |
| `--self-test` | `drop_target=true`，`groups=1`，`failures=0`（同时修掉了自检把「添加图标」格子算成不一致的误报） |
| 单个文件拖入 | `enter=4 over=4 drop=4`（LINK），项数 0→1，落在「其它」，已写 `custom-icons.txt`/`groups.txt` |
| 文件 + 文件夹同批 | 2 项，`custom-icons.txt` 两行，分组两行 |
| 重复拖入同一批 | 提示「跳过 2 项」，`custom-icons.txt` 仍两行 |
| 悬停画面 | `drop-hover.bmp` 截图可见整块绿色描边与标题行高亮 |
| 单元测试 | `cargo test --release --features shell --bin litefences-desktop` 通过 |

未验证：真实 Explorer 跨窗口手势的鼠标操作（沙箱内无法注入拖动），需人工从资源管理器拖一次确认观感。

## 2026-10-24 第七轮：修「新建分组后软件自己退出」

现象：点「＋ 新建分组」→ 输入名字 → 确定，面板消失、进程直接结束（日志停在 `新建分组「…」` 之后）。

根因：输入对话框 `text_input.rs` 的窗口过程在 `WM_DESTROY` 里调了 `PostQuitMessage(0)`。
对话框和主程序在**同一个线程消息队列**里，这条 `WM_QUIT` 不会被对话框自己的模态循环吃掉，
而是留给主循环 → `GetMessageW` 返回 0 → 常驻进程正常退出。所以看起来像“点一下软件就关了”，也没有崩溃日志。
`hotkey_dialog.rs`（改热键）是同一份写法，同样会退出软件。

修法：

- 两个对话框的 `WM_DESTROY` 改成只置 `closed = true`，不碰主消息队列；
- 对话框状态从 `OnceLock::set`（只能成功一次）改成每次打开都重置：不然第二次打开会直接返回上次的结果；
- 窗口类底色画刷与输入框画刷只建一次/用完释放，不再每次开对话框泄漏；
- 主循环进出各加一行日志（`进入主消息循环` / `主消息循环结束，进程退出`），以后再出现“自己关掉”能一眼分清正常退出和崩溃。

回归：新增 `scripts/Test-NewGroupUi.ps1`（窗口枚举 + `PostMessage` 注入点击与 `WM_COMMAND`，数据目录隔离到 `%TEMP%` 之外的独立目录）。
修复前的构建上跑，一次就在“点完确定”后掉进程；修复后的构建连续建两个分组都正常，面板全程不收起，进程只在最后收到关闭消息时退出：

```
ok: 新建分组「自动测试A」，进程仍在运行
ok: 新建分组「自动测试B」，进程仍在运行
[其它] / [自动测试A] / [自动测试B]
final_alive=False (关闭后应为 False)  → PASS
```

## 2026-10-26：资源管理器重启后的图标状态（M3 一项）

以前 Explorer 重启时只重建托盘图标：面板开着的话，桌面图标会跟着恢复可见，而我们记的 `icons_hidden=true` 没变，
等面板收起时再切一次反而把桌面图标藏住了。

现在 `TaskbarCreated` 里额外做两件事：

- 桌面图标应该藏着的（面板正显示、`icons_hidden` 为真）就再藏一次；DefView 刚重建时可能还不存在，
  所以用 700 ms 的定时器重试最多 3 次，仍失败就记 `icons_hidden=false` 交给下次唤出，不会卡在错误状态。
- 顺手重扫一遍桌面图标（集合可能变了）。

验证（不重启真实 Explorer，直接给宿主窗口发 `RegisterWindowMessage("TaskbarCreated")`）：日志出现
`收到 TaskbarCreated（资源管理器重启）` 与 `资源管理器重启后已重新隐藏桌面图标`，随后收起面板、桌面图标恢复可见，
进程正常退出。`--self-test` 仍为 `failures=0`。

## 2026-10-26：常驻内存回收与资源占用实测（M4 一项）

问题：整屏静态帧缓存（32 位 DIB，2560×1440 ≈ 14.7 MB）和界面字体只在面板显示时有意义，
但以前收起面板后仍然留着，常驻私有内存会从 ~8 MB 涨到 ~22 MB。

修法：`hide_panel` 末尾调用 `free_caches()` —— 删内存 DC、删位图、删字体、丢掉磨砂底板，
下次唤出在 `WM_PAINT` 里按需重建（耗时几毫秒）。

实测（部署 exe，`--self-test` 之外不显示面板；数据目录隔离）：

| 状态 | 私有内存 | 工作集 | 句柄 |
| --- | --- | --- | --- |
| 常驻（刚启动，未唤出） | 7.7 MB | 34.0 MB | 400 |
| 面板显示中（84 个图标） | 22.1 MB | 63.1 MB | 403 |
| 收起后 2 秒 | 7.9 MB | 48.9 MB | 403 |

- 空闲 CPU：收起后 10 秒内 CPU 时间增量 0 ms。
- 结论：常驻私有内存 < 20 MB 的目标满足；面板打开时的 22 MB 是整屏缓存，收起即归还。

## 2026-10-26（第二轮）：内容放不下时可以滚动

以前图标多、分组多、或者屏幕小的时候，布局会一直缩格子，缩到下限还得把最后几行挤出屏幕外（不可见也点不到）。

现在：

- 格子最小只缩到 96×104（按 DPI 缩放），再小名字就看不清了；剩下的内容改为**滚动**查看。
- 滚轮滚动（面板不抢焦点，靠系统「悬停时滚动非活动窗口」把 `WM_MOUSEWHEEL` 送进来），一次约半格高；
  右侧出现细滚动条显示位置；内容不超高时滚动条不出现。
- 内容区裁剪到工具条/横幅以下，滚动时不会画到工具条上；滚到底留出提示条的高度。
- 列数不再超过「最大一组的项数」——以前会开出一堆空列，把每组挤到左边。

验证：

- 新增单测 `overlay::layout_tests::tiles_fit_inside_the_panel`：在 2560×1440 / 1920×1080 / 1366×768 / 1280×720，
  1～8 个组、84～200 项的组合下，要求每格横向不越界、纵向落在 `content_height` 内且能被滚动覆盖。
  （改之前 1920×1080、3 组、120 项就会越界 62 px，测试先红后绿。）
- 实机截图：12 个组、84 个图标时内容超出一屏，滚动前 `scroll-before-2026-10-26.png`、滚动 5 格后
  `scroll-after-2026-10-26.png`（内容上移约 250 px，右侧滚动条下滑）。

## 2026-10-27：标题吸顶 + 文件夹入口

### 分组标题吸顶

滚动时，已经滚出顶部、但内容还在可见区的那一组，标题会固定在内容区顶部（带不透明底色，压在图标之上），
点击它照样能折叠，右键能重命名/折叠/移除。换了组就换吸顶的那一条。

### 文件夹入口（只读）

托盘菜单（面板左上角「设置」也是同一个菜单）新增「添加文件夹入口…（只读展示目录内容）」：

## 2026-10-27（第四轮）：打开面板的入场动画

以前只有亚克力模式有“浓度淡入”，默认的磨砂底板是直接“啪”地出现。现在所有虚化模式都有入场动画：

- 面板整帧用 `AlphaBlend`（msimg32，`SourceConstantAlpha`）从 0 叠到 255，时长 220ms，ease-out；
  动画期间工具条/搜索框也画进静态缓存，跟着一起淡入，不会出现“面板淡入、工具条瞬现”。
- 因为窗口本身不透明、又不能改回分层窗口（会让 GDI 文字整段丢失），所以这里是**逐帧把缓存位图按不透明度叠到屏幕**，
  文字和图标都是位图的一部分，不存在被合成丢弃的问题。
- 动画期间点击仍按原来的 `animating()` 拦截，不会误触。

验证：连续采样面板左上角像素（这块在游戏画面上是纯白，面板是橙色横幅），可见 255→187,88,72→180,60,40 的过渡帧；
动画结束后 `static_dirty` 重画一版不含工具条的静态帧。

## 2026-10-29：把入场动画做顺

用户反馈“不太流畅”。测下来有三个原因，逐个改掉：

1. **每帧在缩放整屏**：为了做 96%→100% 的缩放，每帧要对 2560×1440 重采样一次，
   日志实测 `入场动画单帧偏慢：39ms`——240ms 的动画只有 6 帧左右，必然卡。
   现在改成 1:1 叠加，单帧 2–3ms。
2. **叠加上一帧导致曲线跑偏**：每帧都 blend 到“上一帧结果”上，视觉不透明度是复合的，
   实际 80ms 就冲到接近满，看起来像“闪一下”。现在按目标值反算每帧增量：
   `step = (target - current) / (1 - current)`，曲线严格走 ease-out 的 240ms。
3. **WM_TIMER 抖动**：靠 16ms 定时器推帧，实测出现 94→98→114→145→177→193→224→239ms 这种
   16/31ms 交替的空档（约 33fps 且不均匀）。现在改成**同步循环 + `DwmFlush()`** 跟随合成器节奏，
   实测 `入场动画：23 帧 / 240ms`（≈10ms 一帧，约 96fps），动画结束才把消息让出来。

顺带：唤出前先把静态帧预热进缓存（省掉动画第一帧的整屏重绘），第一帧仍是混合冷启动，个别 30ms，
但那一下面板还不透明度≈0，看不见。日志保留 `入场动画：N 帧 / Xms` 与 `单帧偏慢` 便于以后回归。

### 补充：只淡入“看不出来”

1:1 淡入虽然顺，但磨砂底本来就是同一张桌面的模糊版，肉眼几乎看不出变化——用户反馈“根本没动画”。

所以加回**位移**（不重采样）：整帧从下方 20dp 滑到原位，同时淡入。顶部露出的那一条用底板位图
按同一透明度补（`Backdrop::blend_into`，只缩放那条小区域），既不会露出清晰桌面，也不会掉帧。

实测 `入场动画：27 帧 / 240ms`（≈9ms/帧），只有第一帧混合冷启动偶发 25ms，而那一下不透明度≈0。

### 补：开场“字会闪”

原因是**第一帧窗口表面是空的**：新建的窗口在第一次 paint 之前，DWM 合成出来的内容是黑的，
而入场动画第一帧的不透明度≈0，`AlphaBlend` 不改目标像素，于是屏幕上先闪过一帧黑（看起来像字闪一下）。

修法：唤出时（桌面图标已隐藏之后）抓一张**整屏原图** `ScreenBase`，动画**只在第一帧**贴它当底，
后续帧仍走叠加；这样第一帧就是“桌面原样”，之后再淡入。

注意别每帧都贴：实测每帧多一次整屏拷贝会把帧数从 25 砍到 12。
当前实测 `入场动画：24–26 帧 / 244ms`。

## 2026-10-29（第三轮）：改成 MSI 安装

原来的 `install.ps1` 只能在 PowerShell 里跑，双击安装体验一般，也进不了「设置 → 应用」的规范列表。
现在用 WiX v5 出 MSI：

| 文件 | 作用 |
| --- | --- |
| `packaging/LiteFences.wxs` | 打包定义（WiX v5 语法，`Scope="perUser"`） |
| `packaging/使用说明.txt` | 打包进去的说明书（和便携目录那份保持同步） |
| `scripts/Build-Msi.ps1` | 构建脚本：版本号取自 Cargo.toml，暂存 exe + 说明，调 `wix build` |

口径：

- **按用户安装**到 `%LOCALAPPDATA%\Programs\LiteFences`，不需要管理员权限；
- 开始菜单快捷方式（`程序\LiteFences\LiteFences.lnk`）+ 桌面快捷方式，图标直接取自 exe；
- `MajorUpgrade` 不允许降级；卸载走 MSI，**不动** `%LOCALAPPDATA%\LiteFencesDesktop` 的配置；
- 组件 KeyPath 用 HKCU 下的注册表值（快捷方式本身不能当 KeyPath）。

验证（本机实测整轮）：

1. `msiexec /a` 解包：产物落在 `LocalApp\Programs\LiteFences\`，exe 与说明书齐全；
2. 先 `卸载.cmd -Quiet` 清掉旧脚本安装 → `msiexec /i ... /qn` → 文件、两个快捷方式、
   `设置 → 应用` 里的 LiteFences 0.1.0（Publisher=Ltsunahi）都在；
3. 已安装的 exe 跑 `--self-test`：`failures=0`；
4. `msiexec /x {ProductCode} /qn` → 程序目录与桌面快捷方式都被清掉，配置目录保留。
