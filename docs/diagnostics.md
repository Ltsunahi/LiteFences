## 诊断设计

`core/error_text.rs` 为全部 AppError 变体提供稳定 ASCII 码与中文建议，不显示原始路径或嵌套负载。`diagnostics.rs` 仅接受结构化白名单事件，不接受任意用户文本。

日志为配置目录内固定的 `diagnostics.log`，包含格式头、Unix 秒数、程序版本、启动/加载/保存/停止事件、加载来源/可写标志及会话保存序号、错误码。新记录不包含路径、文件名、分组标题或环境变量内容，也不上传数据。不安装遥测或新增第三方依赖。

日志由已有 I/O 工作者持有，在配置写锁保护下打开，不增加线程或 UI 磁盘操作。结果通知前通过原子状态发布日志可用性，窗口能区分记录中、达到上限和不可用。正常停止先关闭日志再释放 FileStore，最后回报 Stopped。

单文件最多 65,536 字节；写入每条记录前检查剩余空间。达到上限关闭句柄、停止追加，跨启动仍不清空；可能保留少量不足一条记录的空余字节。没有轮换、自动删除或无限生成日志文件。若用户希望重新记录，可在完全退出后自行备份该文件并腾出原名称；本轮没有删除日志。

打开时不截断，拒绝重解析点、硬链接、多种异常文件类型、未知头、过大文件及末尾残缺记录。预先存在的超限文件保持原样，不保证它本来就在限额内。写失败停用日志；后续不重试覆盖，不影响配置保存。日志是尽力诊断，不逐条 fsync，不承诺崩溃/断电后每条事件都可恢复，也不是配置恢复事务日志。

无法取得数据目录或写锁时不打开日志，UI 显示加载错误及“诊断日志不可用”。没有全局后备日志，也不记录线程创建前或进程崩溃后的所有故障。日志未抵御恶意同用户进程/文件系统竞争；本项目不把这些措施作为安全沙箱。

上述为修复前记录。修复后已复测可见窗口中的鼠标保存、Ctrl+S、Tab、Enter、Esc；详情见下一节。混合 DPI、多屏、屏幕阅读器、Win+D、Explorer 重启和完整 S1 性能均仍未验收。GDI 绘制的状态文字通过截图观察，不宣称已经具备完整辅助技术支持。

## 2026-09-24 焦点修复与复测

首次启动的 Ctrl+S 成功，鼠标保存后按键失效。在已聚焦的保存按钮上，原代码直接 `EnableWindow(button, false)`；Windows 会清除该按钮的焦点，重新启用也不会自动恢复。现改为禁用前将焦点移交本窗口，保存完成时只在本窗口仍位于前台且父窗口仍有焦点时恢复按钮焦点。窗口失活时取消待恢复状态，防止用户切换应用后抢焦点。参见 [微软 Window Features 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/window-features)。

新增 2 个回归测试（含隐藏自有 HWND 的旧行为复现和新焦点交接），Debug/Release 全 feature 各 94 项通过。在独立可见测试目录中依次操作：鼠标保存 #1、Ctrl+S #2、Tab 聚焦按钮、Enter 保存 #3、Esc 退出。`artifacts/keyboard-fixed-35baea0567d74be395207ef641c229d6/diagnostics.log` 有对应三次 `result=ok` 和 `stop`，结束后无该应用测试进程。

P1-03 的界面/键盘出口完成。只读状态的快捷键额外复测因为自动审批额度耗尽未能启动，未计为已验证。它在代码中仍受 `Session::can_save` 保护，已有只读 UI 灰色按钮与存储后端拒写测试。P0 桌面融合与完整 S1 内存、CPU 预算继续待验收。
